# 📦 Sürüm v1.5.3 — JSON Veri Yedekleme Paylaşımı & Android Scoped Storage NullPointerException Çözümü

**Modül:** `SettingsScreen` / `backupRestoreService.ts` / `useSettingsController.ts` / `Android Native FileProvider & Storage`

## 🎯 1. Problem & Kök Neden Analizi (Root Cause Analysis)

### 🔴 Bildirilen Hata:
Kullanıcı Ayarlar (`SettingsScreen`) ekranından **"Veri Yedekleme & Aktarım"** seçeneğine dokunduğunda ekranda şu hata modalı patlamaktaydı:
> **Başlık:** `Yedekleme Hatası`  
> **Mesaj:** `Attempt to invoke virtual method 'java.lang.String android.net.Uri.getScheme()' on a null object reference`

### 🔍 Kök Neden:
1. `mobile/src/services/backupRestoreService.ts` dosyasında `Share.open` metodu `url: 'data:application/json;base64,...'` Base64 Data URL formatında çağrılmaktaydı.
2. `react-native-share` kütüphanesinin Android native modülünde (`ShareFile.java` ve `ShareIntent.java`):
   - `ShareFile.java` `getURI()` metodu çalıştığında varsayılan olarak `useInternalStorage: false` olduğu için harici dizini (`this.reactContext.getExternalCacheDir()`, `Environment.DIRECTORY_DOWNLOADS`) oluşturmaya çalışıyordu.
   - **Android 11–15 (API 30–35) Scoped Storage** kısıtlamaları nedeniyle izin verilmediğinden `IOException` fırlatılıp yakalanıyor ve `getURI()` fonksiyonu `null` dönüyordu.
   - `ShareIntent.java` satır 186'da `ClipData.newUri(resolver, "File", uriFile)` çağrılıyor; ancak `uriFile` null olduğu için Android OS içindeki `ClipData.newUri` metodu `uri.getScheme()` satırında **NullPointerException** fırlatıyordu.

## 🛠️ 2. Geliştirilen Çözüm ve 3 Kademeli Koruma Mimarisi (Multi-Tier Fail-Safe)

### 🛡️ 1. Kademe (Tier 1 - useInternalStorage: true):
`Share.open` parametrelerine `useInternalStorage: true` eklendi. Bu sayede Android 11–15 işletim sistemlerinde depolama iznine (`WRITE_EXTERNAL_STORAGE`) gerek kalmadan doğrudan uygulamanın dahili özel önbelleği (`context.getCacheDir()`) kullanılır ve FileProvider üzerinden güvenli `content://` URI üretilir.

### 🛡️ 2. Kademe (Tier 2 - Plain Text Intent Fallback):
Eğer kullanıcının işletim sisteminde dosya paylaşım intent'i herhangi bir sebeple engellenirse, JSON metni `type: 'text/plain'` olarak sistem paylaşım menüsüne aktarılır.

### 🛡️ 3. Kademe (Tier 3 - Panoya Kopyalama Kalkanı):
Eğer cihazdaki tüm sistem paylaşım diyalogları arızalanırsa, yedek JSON verisi `expo-clipboard` vasıtasıyla sessizce ve güvenle panoya kopyalanır (`Clipboard.setStringAsync`) ve kullanıcıya *"Yedekleme verileriniz panoya kopyalandı"* bildirimi verilir.
