## 🐞 1. `rollingHorizonScheduler` — aynı isimde bozuk ikiz fonksiyon (C1)

`isMedicineScheduledForDate` **iki yerde** tanımlıydı:

- ✅ `utils/timeCalculator.ts` — doğru; `scheduleType` (`daily` / `specific_days` /
  `interval_days` / `cycle`) üzerinden çalışıyor. Gerçek alarm planlaması, ana
  ekran, takvim ve store self-heal bunu kullanıyor.
- ❌ `utils/notifications/rollingHorizonScheduler.ts` — bozuk:

```ts
switch (medicine.frequency) {        // frequency: number (günde kaç kez)
  case 'daily':          return true;   // hiç eşleşmez
  case 'specific_days':  ...            // hiç eşleşmez
  case 'interval':       ...            // isim de yanlış: 'interval_days'
  case 'as_needed':      return false;  // hiç eşleşmez
  default:               return true;   // ← HER ZAMAN buraya düşer
}
```

`medicine.durationDays` alanı `Medicine` tipinde **hiç yok**; aynı dosyadaki
`m.frequency !== 'as_needed'` filtresi de her zaman `true` idi (tipte "ihtiyaç
halinde" diye bir kavram yok).

**Etkisi:** alarm kurulumu etkilenmiyordu, ama teşhis panelindeki
**"14 Günlük Planlanan Doz"** sayısı `specific_days` / `interval_days` / `cycle`
ilaçlarda her günü sayarak **şişiyordu**. Panelin varlık sebebi kullanıcıya
"alarmların kurulu" güvencesi vermek; yanlış sayı göstermesi kabul edilemez.

**Çözüm:** bozuk kopya silindi, `timeCalculator`'daki tek kaynak import edildi.
Test dosyası da uydurma şemadan (`frequency: 'daily'`, `durationDays`, `times[]`)
gerçek tipe taşındı ve yeni bir senaryo eklendi: *"gün aşırı ilaç projeksiyonda
da her gün GÖRÜNMEZ"* → `dayOffset` dizisi `[0, 2, 4, 6]` olmalı. Bozuk ikizin
asıl semptomunu doğrudan yakalıyor.

## 💥 2. `caregiverNotificationService` — her bakıcı bildiriminde `ReferenceError`

```ts
const { type, medicineName, patientName, scheduledTime } = data;
...
title: `⚠️ ${patient} İlacını Kaçırdı`,   // `patient` diye bir değişken YOK
```

Beş başlıkta (missed / skipped / taken / snoozed / schedule_updated) tanımsız

**Çözüm:** `patientName` kullanılıyor; boş/boşluk geldiğinde nötr bir ifadeye
düşüyor (`Hastanız`). 9 senaryoluk yeni test dosyası: beş bildirim tipinin
başlığı, hasta adı yok/boşluk halleri, gövde metni ve ISO zaman damgasının
`HH:mm`'e çevrilmesi.

## 💥 3. `BatchMedicineImportModal` — TDZ: modal açılışında `ReferenceError` riski

`handlePickImage` (satır 64) bağımlılık dizisinde `handleAddNewItem`'ı
kullanıyordu ama o callback **156. satırda** tanımlıydı. `useCallback`'in
bağımlılık dizisi render sırasında değerlendirildiği için değişken henüz
TDZ'deydi (tsc: TS2448 + TS2454).

**Çözüm:** `handleAddNewItem` tanımı yukarı taşındı. Cihazda doğrulandı: modal
açılıyor, "⚡ Hızlı Toplu Giriş Formunu Aç" satır ekliyor
("Tespit Edilen İlaçlar (1)"), logcat'te `ReferenceError` / `FATAL` yok.

## 📌 10. Açık kalan maddeler

- **ESLint 54 hata:** büyük kısmı `no-useless-escape` (regex'lerde gereksiz
  kaçış), `no-empty` (boş catch blokları) ve `unused-imports`. Hiçbiri
  davranışsal değil ama CI kapısı için temizlenmeli. İki tanesi dikkat
  isteyebilir: `healthVaultCrypto.ts`'de `TextEncoder`/`btoa`/`atob` `no-undef`
  (RN'de global var, ESLint ortamı bilmiyor) ve `ereceteParser.ts`'de
  `no-dupe-else-if` (asla çalışmayan dal — **gerçek mantık hatası olabilir**).
- **C3 — çift startup:** `App.tsx` ve `useBootRecovery` aynı startup cleanup'ı
  yapıyor; her açılışta iki `reRegisterAllAlarms` fırtınası (logcat'te aynı
  bildirim kimliklerinin 2–4 kez iptal edildiği ölçüldü).
- **C2 — snooze:** `snooze-` kimlikleri native iptal yoluna ulaşmıyor, ana
  alarmla aynı requestCode'u paylaşıyor.
- **C4 — `syncFromCloud` ham `set()`:** ayar yan etkileri atlanıyor; ayrıca
  bulut merge'i koşulsuz kazanıyor (alan bazlı zaman damgası gerekiyor).
- **B1/B2 kapandı**, **B3/B5/C1/C5 kapandı**, eski paket cihazdan kaldırıldı.
