## 🚨 4. Doğrulama Sırasında Bulunan ENGELLEYİCİ Hata (henüz düzeltilmedi)

`utils/notifications/cancel.ts` içindeki `cancelNotification()`, bildirim id'sini **tire ile bölerek** ilaç/hatırlatma id'sini geri çıkarmaya çalışıyor:

```ts
const parts = notificationId.split('-');
const medicineId = parts[1];
const reminderTimeId = parts.slice(2).join('-');
```

Kimlikler tire içerdiği için bu geri çözümleme **ilkesel olarak yanlış**. Cihaz logcat kanıtı:

```
cancelNativeAlarm: Alarm iptal edildi (test - medicine-test-reminder)
cancelAlarmNotification: iptal edildi (id=1702697064, test/medicine-test-reminder)
...
AlarmReceiver: FullScreen notification posted with id: 726112856
```

- `alarm-test-medicine-test-reminder` → medicineId=**`test`**, reminderTimeId=**`medicine-test-reminder`**
- Gerçek ilaçlarda UUID: `alarm-01a057f1-3ae0-...` → medicineId=**`01a057f1`**, gerisi çöp
- Sonuç: `cancelNativeAlarm` ve `cancelAlarmNotification` **yanlış requestCode** ile çağrılıyor; ne AlarmManager alarmı ne de tam ekran taşıyıcı bildirim iptal ediliyor (üretilen id 1702697064, gerçek id 726112856).

Bu hata **adım 2'den önce vardı** (`cancelNativeAlarm` çağrısı zaten oradaydı); adım 1'de eklediğim `cancelAlarmNotification` aynı bozuk çözümlemeyi miras aldı. `useAlarmController.clearAlarmNotifications` id'leri doğrudan geçtiği için o yol **doğru** çalışıyor.

**Öneri:** id'leri geri çözümlemeyi tamamen bırakmak — `cancelNotification`'a opsiyonel `{ medicineId, reminderTimeId }` parametresi eklemek veya ayrı bir `cancelAlarmFor(medicineId, reminderTimeId)` fonksiyonu tanımlamak. Adım 3'te "toggle değişince zamanlanmış alarmları yeniden planla" işi bu yola dayandığı için **adım 3'ten önce** kapatılmalı.
